# Upcoming fixtures and odds

The public page is `https://gerball.co.uk/#upcoming`. It reads stored daily odds through the `gerball-upcoming-fixtures` Edge Function and opens the existing historical team profiles using reviewed provider-to-history names.

## User interface

- Five markets: home win, draw, away win, over 2.5 goals and under 2.5 goals.
- Highest captured price for each market, with the bookmaker and source update time.
- Expand a fixture to compare every captured bookmaker. The larger comparison payload is requested only when needed.
- League, UK match date, market group and team search filters; search recognizes both provider and historical names.
- Current-season games, points per game and the last five league results, oldest to newest.
- Twenty-four cards per page, with a “Show more fixtures” control.
- Capture time, collection age and partial/stale collection labels. These are daily snapshots, not a live price feed.
- Team links select the correct country, league and season in the historical profile. The cutoff is the earlier of today in London and the day before kickoff. The return button retains fixture filters.
- Returning to this view reuses the workspace and refreshes expired data, including across UK midnight or the daily noon collection boundary. Valid filters and open comparisons are retained; started fixtures are removed.
- Match analysis includes a direct **Captured prices** action for the same event. See [Captured prices](captured-prices.md).

The bookmaker display is informational. No probability, expected value, strategy approval, wager or prospective prediction is generated by this page.

Bookmaker details and the list must share the same collection date and collection activity time. A newer same-day collection prompts a fixture refresh instead of mixing versions. Reloading aborts earlier detail requests and clears their cache, and delayed responses cannot repopulate the new list's cache.

## Data and permissions

`supabase/migrations/20261124194500_gerball_upcoming_fixtures.sql` adds:

1. `public.gerball_team_aliases`, with row-level security and service-role SELECT access. Reviewed mappings come from `data/team-aliases.json`; researched club-identity mappings retain primary-source URLs in that file.
2. `public.gerball_upcoming_data(p_league text, p_days integer, p_event_id text)`, an explicitly service-only, SECURITY INVOKER read function with an empty search path.

The RPC uses the newest completed or partial collection that contains snapshots. It excludes fixtures that have started, bounds the horizon to 1–31 days, and returns a deliberately selected public payload. List requests omit bookmaker matrices; an event request includes them. Each best-price tie is resolved by newest provider update, newest capture and bookmaker key.

An explicit valid alias takes priority over exact-name matching. Every canonical target must exist in historical records for the same league. The query first checks the small relevant season slices using existing indexes, then probes older history only when necessary. Unknown future provider names remain visibly unmatched until reviewed; arbitrary fuzzy matches are never accepted automatically.

Season codes follow July–June. Statistics use completed matches from the fixture's season, dated no later than today in London and strictly before the fixture's London date. Null statistics remain null when there are no usable records. No historical tables, historical results, collector schedules or importer functions are modified by this migration.

## Public endpoint

```text
GET https://hdueztssmsvvxkwqgcnm.supabase.co/functions/v1/gerball-upcoming-fixtures
GET https://hdueztssmsvvxkwqgcnm.supabase.co/functions/v1/gerball-upcoming-fixtures?league=E0&days=14
GET https://hdueztssmsvvxkwqgcnm.supabase.co/functions/v1/gerball-upcoming-fixtures?event_id=EVENT_ID
```

`days` defaults to 14. The server permits GET and CORS preflight only, validates all query parameters and calls one fixed read-only RPC. It uses Supabase's built-in service-role credential exclusively on the server. There are no provider calls at page load and no new API secrets to configure.

The endpoint intentionally has `verify_jwt = false`: its sole purpose is the public read-only projection. Raw odds tables, run logs and alias records remain inaccessible to anon/authenticated database roles. Successful responses may be cached for 60 seconds; error responses are not cached and never include database internals or credentials.

## Deployment

Production project: `hdueztssmsvvxkwqgcnm`. Frontend: GitHub `MaviUK/gerball.co.uk`, Netlify project `footydata` (`75a1e8b1-ef6a-4606-8947-ac377e3a87b3`).

Apply the migration before deploying the endpoint and publishing the frontend. For the initial installation, the migration was applied through Supabase's connected migration API and the function through its deployment API. The committed migration timestamp matches the recorded production migration version.

With the Supabase CLI authenticated to the same project, equivalent future deployment commands are:

```bash
supabase link --project-ref hdueztssmsvvxkwqgcnm
supabase db push --dry-run
supabase db push
supabase functions deploy gerball-upcoming-fixtures --project-ref hdueztssmsvvxkwqgcnm
```

Review the migration plan before applying it; already recorded migrations are skipped. The function's public-read setting is committed in `supabase/config.toml`.

Publish frontend changes through the existing `main` branch Git deployment. Netlify serves the repository root with no frontend build command. The required assets are `assets/upcoming.js`, `assets/upcoming.css` and `assets/upcoming-bridge.js`; `index.html` loads them and adds the new view/navigation entry.

```bash
node scripts/check-site.cjs
node --test scripts/check-upcoming-endpoint.mjs scripts/check-upcoming-ui.mjs scripts/check-upcoming-bridge.mjs scripts/check-team-aliases.mjs
```

The existing validation workflow runs these alongside collector and historical benchmark checks. The site check also verifies shared export handlers are declared at page scope, preventing a previously discovered startup exception from disabling navigation.

For full alias verification against a fresh stored-data export:

```bash
node scripts/check-team-aliases.mjs --data /path/to/team-data.json
```

The export contains `odds_teams`, `history_teams` and `current_season_teams` arrays of league/team pairs. On 24 November 2026, all 326 provider pairs resolved to current-season records: 143 exact names and 183 reviewed aliases.

Live verification confirmed RLS enabled, no anon/authenticated access to the RPC/raw snapshots/aliases, 211,600 preserved historical rows, 13,821 preserved snapshot rows and the unchanged active daily collector schedule. Fixture counts decrease as kickoff times pass; the UI excludes newly started fixtures when filtering or refreshing its rendered list.
